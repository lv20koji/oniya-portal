# 機能仕様: おにホーム（001-oni-home）

配信者おにや（o-228）の放送を追うための個人用ポータルサイト。
カトホーム（web.katohome.jp）の「日付別アーカイブ一覧」という構成を参考にし、文言・デザイン・データはすべてオリジナルとする。

## 確定した決定事項（2026-10-31 ユーザー確認済み）

1. **名称と公開先**: サイト名は「おにホーム」。リポジトリ `lv20koji/oniya-portal`、公開URL `https://lv20koji.github.io/oniya-portal/`。
2. **更新方式**: APIは使わず、Muse が1日2回（朝・夜）公開情報を確認して broadcasts.json を更新する。サイトには「最終チェック日時」を表示し、ライブ状態は最終チェック時点のものとして扱う。
3. **対象ソース**:
   - YouTube メインチャンネル（o-228おにや、UCLiQ--EXgzUV03q5jKQYWcw）
   - YouTube サブチャンネル「天才おにや」（UCC0FNUII8Zp2OAc7IaetICg、切り抜き＋ライブアーカイブ）
   - Twitch（oniyadayo）: 直接取得ができないため FollowBoard / TwitchTracker 経由で確認
   - X（@oniyanogame）: 毎回確認に試みる（ベストエフォート）。読めなかった回はデータに `xChecked: false` を記録する
4. **自分用機能を含む**: 放送ごとに「見た／あとで見る／途中」の状態とメモを付けられる。保存は localStorage。一覧に統合表示し、JSON エクスポート／インポートに対応する。
5. **一覧デザイン**: 日付グループ（新しい順）。各行にタイトル、長さ（分かれば）、カテゴリタグ（株／ゲーム／雑談／シャドバ等）、配信中なら「放送中」バッジ、元動画へのリンクを表示する。
6. **既定事項（異論なし）**: サムネイルは YouTube フィードの画像を表示する。初期収録（バックフィル）は初回取得で得られた範囲（RSS 直近約15件／チャンネル＋FollowBoard の一覧）までとし、深い過去の掘り起こしはしない。

## ユーザーストーリー

### US1: 最新の放送を一目で追う（P1）
ファンとして、サイトを開いたら最近の放送が日付順に並んでいて、タイトル・カテゴリ・サムネイルから見たいものをすぐ選べる。
- 受け入れ条件:
  - トップに最終チェック日時が表示される。
  - 放送が日付グループ（新しい順）で並び、各行から元の動画／配信ページへ飛べる。
  - 配信中の放送があれば先頭に「放送中」バッジ付きで表示される（最終チェック時点）。

### US2: カテゴリで絞り込む（P2）
株ライブだけ、ゲームだけ、のように関心のあるカテゴリに絞って一覧を見たい。
- 受け入れ条件:
  - カテゴリフィルタ（すべて／株／ゲーム／雑談／シャドバ／その他）で一覧が絞り込める。
  - 状態（未設定／見た／あとで見る／途中）でも絞り込める。

### US3: 自分の視聴記録を付ける（P1）
各放送に「見た／あとで見る／途中」とメモを付け、次に開いたときも残っていてほしい。
- 受け入れ条件:
  - 状態とメモは localStorage（キー `onihome.logs.v1`）に保存され、再訪時に復元される。
  - 状態ごとの件数（全件／見た／あとで見る／途中）が表示される。
  - JSON エクスポート／インポートで記録を別端末へ移せる。
  - 記録は外部送信されない。

### US4: 公式への導線（P2）
配信本体や告知へすぐ行けるよう、公式リンクがまとまっている。
- 受け入れ条件:
  - ヒーロー部に Twitch、YouTube メイン、天才おにや、X、FollowBoard へのクイックリンクがある。

### US5: データが新しいと分かる（P2）
情報がいつ時点のものか分かり、古い情報を最新と誤解しない。
- 受け入れ条件:
  - 最終チェック日時が常時表示される。
  - X を確認できなかった回は、その旨がデータ上区別できる（meta.xChecked）。

## 範囲外

- 配信開始のプッシュ通知、リアルタイムのライブ判定（静的サイト＋定期チェックのため）。
- Twitch VOD の完全な網羅（取得手段が限られるため、取れた範囲のみ）。
- コメント、いいね等の SNS 機能。決済・課金要素。
- カトホームの文言・デザイン・データの流用。

## 成功条件

- スマートフォンで開いて一覧・絞り込み・状態付けがストレスなく操作できる。
- broadcasts.json の全エントリが実在の取得データであり、出典と取得時刻を持つ。
- 追加課金なし、APIキーなしで運用が回る。
